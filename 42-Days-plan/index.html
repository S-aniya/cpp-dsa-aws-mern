Phase 1

Document ingestion + chunking

The pipeline starts by loading raw documents (PDFs, text, DOCX). Raw text is extracted, cleaned (removing headers, footers, extra whitespace), then split into overlapping chunks so no context is cut mid-sentence.

Load with PyPDFLoader or UnstructuredFileLoader (LangChain)
Clean: strip boilerplate, normalize whitespace, remove page artifacts
Chunk: RecursiveCharacterTextSplitter(chunk_size=512, chunk_overlap=64)
Each chunk carries metadata: source filename, page number, chunk index
LangChain document loaders + splitters — James Briggs
Phase 2

Embeddings + vector store

Each chunk is converted to a dense vector (embedding) that captures semantic meaning. Similar chunks end up geometrically close in vector space. These vectors are stored in FAISS (local, fast) or ChromaDB (persistent).

Use HuggingFaceEmbeddings("all-MiniLM-L6-v2") — free, no API key, 384-dim
Or OpenAIEmbeddings("text-embedding-3-small") — better quality, costs money
Store: FAISS.from_documents(chunks, embeddings) — index saved to disk
For upgrade: ChromaDB with persist_directory for cross-session retrieval
Vector databases and FAISS — Sam Witteveen
Phase 3

Retrieval — query → chunks

When a user asks a question, it is embedded with the same model. FAISS does nearest-neighbour search and returns the top-k most semantically similar chunks. This is the "R" in RAG.

Embed query → similarity search → top-k=4 chunks returned
Upgrade: Hybrid search — BM25 (keyword) + dense (embedding), weighted merge
Upgrade: Query rewriting — LLM rewrites ambiguous query before retrieval
Upgrade: MMR (Maximal Marginal Relevance) for diverse, non-redundant results
Advanced retrieval techniques — LangChain channel
Phase 4

Generation — chunks → answer with citations

The retrieved chunks are injected into a prompt template alongside the user's question. The LLM generates a grounded answer. Citations are extracted from chunk metadata and shown to the user — this is the biggest interview differentiator.

Prompt template: "Answer using only the context below. Cite sources. Context: {context} Question: {question}"
LLM: ChatOpenAI(model="gpt-3.5-turbo") or free: HuggingFaceHub(repo_id="mistralai/Mistral-7B-Instruct-v0.2")
Parse response to extract [Source: filename, Page: N] citations
Upgrade: Add memory with ConversationBufferMemory for multi-turn chat
RAG with citations from scratch — Andrej Karpathy style walkthrough
Phase 5

Architecture + improvements you already built vs what to add

Your existing RAG project likely covers Phases 1–4. The things that make it FAANG-level are the upgrades below. Each one is a concrete interview talking point.

Hybrid search (BM25 + FAISS) → shows you understand retrieval tradeoffs
Query rewriting → shows understanding of LLM as orchestrator, not just generator
Caching embeddings and responses (Redis or dict-based) → shows systems thinking
Evaluation metrics: RAGAS framework — faithfulness, answer relevancy, context precision
FastAPI backend + Streamlit or React frontend — shows full-stack ability
Docker deployment — shows you can ship, not just prototype
Production RAG — Full pipeline with FastAPI — Rabbitmetrics
